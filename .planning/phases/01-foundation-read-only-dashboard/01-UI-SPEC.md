## Spacing Scale

Pico CSS handles component-internal spacing through its own defaults. The following values govern layout structure and custom overrides written inline or in a minimal `<style>` block.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, badge internal padding |
| sm | 8px | Card inner padding compact, list row gap |
| md | 16px | Card padding, section gaps, main content padding |
| lg | 24px | Between card rows, between page sections |
| xl | 32px | Sidebar width: 200px (see exception) |
| 2xl | 48px | Top-of-page heading margin |
| 3xl | 64px | Not used in Phase 1 |

Exceptions:
- **Sidebar width:** 200px fixed (not a spacing token — structural value for CSS grid column)
- **Two-panel column ratio:** `1fr 2fr` for conversation viewer (conversation list : message pane)
- **Conversation card click target:** minimum 44px height for touch accessibility

**Source:** Defaults from Pico CSS 2.1.1 spec; sidebar width from RESEARCH.md Pattern 4.

## Typography

Pico CSS applies typography to semantic HTML elements. Do not add font classes. These values document what Pico renders with `system-ui` and how to use them.

| Role | Element | Size | Weight | Line Height |
|------|---------|------|--------|-------------|
| Body | `<p>`, `<td>`, `<li>` | 16px | 400 (regular) | 1.5 |
| Label / Meta | `<small>`, `<figcaption>` | 14px | 400 (regular) | 1.4 |
| Heading | `<h2>`, `<h3>` | 20px / 18px | 600 (semibold) | 1.2 |
| Display | `<h1>` (page title) | 28px | 600 (semibold) | 1.2 |

**Weights used: 2** — regular (400) for body/meta, semibold (600) for headings.

**Timestamp rendering:** All `Agent.last_seen`, `Task.created_at`, `Event.created_at` timestamps are ISO strings. Use the `fmt_time` Jinja2 filter (`{{ ts | fmt_time }}`) — renders as `HH:MM:SS` in 24h UTC. Never call `.strftime()` in templates (these are strings, not datetime objects).

**Source:** Pico CSS 2.1.1 typography defaults; RESEARCH.md Pitfall 4.

## Color

Pico CSS manages light/dark themes automatically via `prefers-color-scheme`. Do not hard-code hex values for backgrounds, text, or borders — use Pico CSS custom properties or semantic HTML elements.

The values below define the **semantic roles** and which **Pico CSS variables** to reference when custom overrides are needed.

| Role | Pico Variable | Usage |
|------|---------------|-------|
| Dominant (60%) | `--pico-background-color` | Page background, main content area |
| Secondary (30%) | `--pico-card-background-color` | Agent cards, sidebar `<nav>`, conversation list items |
| Accent (10%) | `--pico-primary` | Active nav link (`aria-current="page"`), agent ONLINE status dot |
| Destructive | `--pico-del-color` (red) | Not used in Phase 1 — no destructive actions |

**Accent reserved for:**
1. Active sidebar navigation link (via Pico's `aria-current="page"` style)
2. Agent `ONLINE` status indicator dot

**Status badge colors** (task board — D-05, using inline style or minimal custom CSS):

| TaskStatus | Background | Text | Semantic Meaning |
|------------|-----------|------|-----------------|
| `queued` | `#e3f2fd` / `#1a3a5c` (dark) | `#0d47a1` / `#90caf9` | Informational blue |
| `running` | `#fff8e1` / `#4a3800` (dark) | `#f57f17` / `#ffcc02` | Warning amber |
| `completed` | `#e8f5e9` / `#1a3a1a` (dark) | `#2e7d32` / `#81c784` | Success green |
| `failed` | `#fce4ec` / `#4a0014` (dark) | `#c62828` / `#ef9a9a` | Danger red |
| `canceled` | `--pico-muted-color` | `--pico-muted-color` | Neutral muted |
| `rejected` | `--pico-muted-color` | `--pico-muted-color` | Neutral muted |

**Implementation note:** Status badges use `<span>` with `style="..."` inline per badge, or a minimal `<style>` block in `base.html`. Do not introduce a separate CSS file in Phase 1.

**Human operator distinction** (HUMAN-02): The human operator `<article>` card at the top of the agent directory uses a left border accent: `style="border-left: 3px solid var(--pico-primary); padding-left: 1rem;"`. Regular agent cards have no border decoration.

**Source:** D-02 (Pico CSS), D-03 (auto dark/light), D-09 (human operator visual separation), RESEARCH.md Pattern 4.

## Layout Contract

**Source:** D-01 (sidebar), D-04 (card grid), D-05 (list + filter), D-06 (two-panel), D-07 (feed).

### Global layout — `base.html`

```
┌─────────────────────────────────────────────┐
│  <div style="display:grid;                  │
│    grid-template-columns:200px 1fr;         │
│    min-height:100vh;">                       │
│  ┌───────────┬─────────────────────────────┐ │
│  │  <nav>    │  <main class="container">   │ │
│  │  sidebar  │  {% block content %}        │ │
│  │  200px    │  page content               │ │
│  └───────────┴─────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

Sidebar `<nav>` contains an `<ul>` with four `<li><a>` links. Active link receives `aria-current="page"` (Pico styles it with accent color automatically).

### Agent directory — `agents.html` / `partials/agent_list.html`

- Human operator: single `<article>` with left-border accent above the grid
- Regular agents: CSS grid, `grid-template-columns: repeat(auto-fill, minmax(220px, 1fr))`
- Each agent card `<article>`: name (`<strong>`), status dot + label, last seen (`<small>`, `fmt_time` filter), skills list (`<small>`)
- Empty state: "No agents connected." centered inside a `<p>` within the grid container

### Task board — `tasks.html` / `partials/task_list.html`

- Filter bar: `<div role="group">` with `<button>` per status (All / Queued / Running / Completed / Failed / Canceled / Rejected)
- Task list: `<table>` with columns: Task ID (truncated), Status (badge), Assignee, Requester, Created
- Active filter button: `aria-pressed="true"` and visually distinguished via Pico's secondary button contrast
- Empty state: "No tasks found." as a table row spanning all columns

### Conversation viewer — `conversations.html`

```
┌────────────────────────────────────────────────────┐
│  <div style="display:grid;                         │
│    grid-template-columns:1fr 2fr; gap:1rem;">       │
│  ┌──────────────┬───────────────────────────────┐  │
│  │ #conv-list   │ #conv-detail                  │  │
│  │ conversation │ message history               │  │
│  │ items        │ (click to load)               │  │
│  └──────────────┴───────────────────────────────┘  │
└────────────────────────────────────────────────────┘
```

- Left panel: `<article>` per conversation, `hx-get="/conversations/{id}/messages"`, `hx-target="#conv-detail"`, `style="cursor:pointer"`
- Right panel initial state: "Select a conversation to view messages." in `<p>`
- Message bubbles: `<article>` per message, sender name in `<strong>`, timestamp in `<small>`, content in `<p>`
- Empty left panel: "No conversations." in `<p>`

### Activity feed — `activity.html` / `partials/activity_feed.html`

- Chronological list, newest at top
- Each event: `<article>` with timestamp (`<small>`, `fmt_time` filter), event type badge, description
- Events without `parts` key (non-message events): render `event.type` name + formatted `event.data` as fallback string — never attempt `event.data.get('parts', [])` without checking `event.type`
- Empty state: "No activity yet." in `<p>`

**Source:** D-05 (htmx partials), RESEARCH.md Pattern 2.

| View | Trigger | Interval | Target | Swap |
|------|---------|----------|--------|------|
| Agent list | `load, every 10s` | 10s | `#agent-list` | `innerHTML` |
| Task list | `load, every 10s` | 10s | `#task-list` | `innerHTML` |
| Task list (filter click) | explicit `hx-get` on button | on click | `#task-list` | `innerHTML` |

| Conversation detail | explicit `hx-get` on item click | on click | `#conv-detail` | `innerHTML` |

**Loading placeholder:** All htmx-managed containers show `Loading...` as initial content before first partial response.

**No JavaScript authored in Phase 1.** All interactivity is htmx HTML attributes only.

## Critical Implementation Constraints

These are not style choices — they are correctness requirements that will cause failures if violated.

1. **Starlette 1.0.0 TemplateResponse signature:** `templates.TemplateResponse(request, "name.html", context_dict)` — request is first positional arg. The old `(name, {"request": request})` pattern raises TypeError.

2. **No `include_router()`:** FastMCP wraps Starlette, not FastAPI. Register each route via `@mcp.custom_route(path, methods)` only.

3. **`is_human` column migration:** `ALTER TABLE agents ADD COLUMN is_human INTEGER NOT NULL DEFAULT 0` with try/except in `Store.__init__()`. Required for existing databases.

4. **Timestamps are strings:** Never call `.strftime()` in templates. Use `fmt_time` Jinja2 filter registered on `templates.env.filters`.

5. **Guard `agent.card`:** Always check `{% if agent.card %}` before accessing card attributes — many agents have no card set.

6. **Event data shape varies:** Check `event.type` before accessing `event.data` keys. Use a string fallback for non-message event types.

7. **htmx SRI hash:** Verify the htmx 2.0.8 hash `sha384-/TgkGk7p307TH7EXJDuUlgG3Ce1UVolAOFopFekQkkXihi5u/6OCvVKyz1W+idaz` against jsDelivr at implementation time before committing `base.html`.
